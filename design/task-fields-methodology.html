Task Types and Fields

How Momentum takes on ClickUp's task model: task types with their own custom fields, statuses, priorities, tags, owners and assignees, start and due dates, templates and recurring tasks. Each point sets out what ClickUp does, what Momentum has today, and the rule proposed for Momentum. The decisions at the end of each point are settled; the plan is spec 023.

Ground rules kept from earlier decisions: every task runs the one pipeline (spec 022); Space stages rename or split it per Space; brand feature switches can hide a field for a brand; English and Arabic for everything new.

Point 1 · the foundation the other points hang on

Task types

ClickUp

  • Each workspace has task types: Task, Milestone, and custom ones (Bug, Request, Deliverable…), each with a name and an icon.
  • Since ClickUp 4.0, a task type carries its own custom fields.
  • A task picks its type when created; changing type changes which fields show.

Momentum today

  • Content types: Post, Carousel, Story, Reel, Video… (a label only).
  • A type already decides two things: its SLA days per stage, and which media board it goes to at Ready For Design (Design, Video or both).
  • No icon, colour, fields or default people per type.

Proposed

  • Content types become Task types, managed in Settings by admins: name (English and Arabic), icon, colour.
  • Each type owns: its custom fields (point 2), its SLA, its media boards, its default priority and tags, and an optional default template (point 8).
  • Milestones are calendar markers, not tasks: a name, a date and a brand, shown on calendars (launches, campaign dates).
  • Existing content types are kept as task types with their SLA and boards; nothing about current tasks changes.
D1, D2. Skipping stages; non-content workPostponed. Every task type runs the full pipeline for now; stage skipping is not built.
Milestone. A launch or campaign dateA calendar marker with a name, a date and a brand. It is not a task: no pipeline, no assignee, no SLA.
Point 2

Custom fields, set by task type

ClickUp

  • Fields are defined once (workspace or Space) and attached to task types and locations.
  • A value belongs to the task, so it shows in every list, board, table and filter the task appears in.
  • Kinds: text, number, money, date, dropdown, labels (multi), checkbox, people, rating, progress, email, phone, URL, relationship, formula.

Momentum today

  • Custom columns live on one sheet each: text, number, date, link, person, choice, checkbox, related task.
  • The value is the sheet's, not the task's: it doesn't show in the task panel, on cards, or in another Space's sheet.

Proposed

  • A field library in Settings: each field has a name (EN/AR), kind and options.
  • Fields are attached to task types, each optional or required from a chosen stage, with an optional default.
  • The value belongs to the task: shown in the task panel, as columns in every sheet the task is in, in filters, sorts and group-by, and optionally on the card.
  • Kinds: today's eight, plus money, multi-choice and rating.
  • Sheet-only columns stay for a team's own notes; any of them can be turned into a task field, keeping its values.
D3. Who creates fieldsAdmins and superusers create fields and attach them to task types.
D4. Required fieldsEach required field has a “Required from stage” setting (for example, Caption required before C-Review). The task can’t move past that stage until the field is filled; the message names the field.
D5. Existing sheet columnsThey stay as they are. “Make it a task field” turns one into a task field when wanted, keeping its values.
Point 3

Custom statuses

ClickUp

  • Each Space, Folder or List has its own statuses, grouped as Not started, Active, Done and Closed.
  • Statuses are free: any names, any order.

Momentum today

  • One pipeline of 11 stages with owners, approvals and SLA.
  • Each Space renames or splits stages for itself (Space stages, spec 022).

Proposed

  • The pipeline stays the only status machine; custom statuses stay Space stages.
  • Each stage gets a ClickUp-style group for reports: To Do = Not started; the C and D stages and F-Check = Active; Ready to Publish and Scheduled = Done; Published = Closed.
D6. Free statusesNone. Custom statuses are Space stages only.
Point 4

Priorities

ClickUp

UrgentHigh NormalLowNo priority

Momentum today

  • Low, Medium, High; new tasks are Medium. A brand can switch priorities off.

Proposed

  • Urgent, High, Normal, Low and No priority, as in ClickUp; Medium becomes Normal.
  • Urgent sorts first on every board and sheet, and tells the assignee at once (push).
  • The task type sets the default for new tasks.
D7. Priority namesUrgent / High / Normal / Low / No priority. Medium becomes Normal.
D8. Urgent and the SLAUrgent doesn’t shorten the SLA. It sorts first and notifies.
Point 5

Tags

ClickUp

  • Coloured tags per Space; many per task; anyone can create one while tagging.

Momentum today

  • No tags. Grouping comes from fields: brand, type, pillar, campaign (project) and theme.

Proposed

  • Workspace tags with a colour, many per task.
  • Shown on cards and in the task panel, as a column in sheets, and in filters and group-by.
  • Typing a new tag name offers to create it. Admins can rename, merge or delete tags in Settings.
  • A brand switch turns tags off for that brand.
D9. Creating tagsEveryone can create a tag while tagging. Admins can rename, merge or delete tags.
D10. Tag scopeOne tag list for the workspace.
Point 6

Owners and assignees

ClickUp

  • Several assignees per task, all equal.
  • No built-in "owner": teams add a People field for it. Watchers follow updates.

Momentum today

  • Owner: answerable for the task; approves at review stages.
  • Assignee: one person doing the work; drives My tasks, the Inbox, SLA badges and Shows in.
  • Followers get updates. Each media board's task has its own assignee.

Proposed

  • Keep one Owner.
  • Allow several assignees. The first is the lead, who gets SLA alerts and whose Spaces the task joins. Everyone assigned sees the task in My tasks and is notified.
  • Workload splits the hour estimate evenly across the assignees, unless hours are set per person.
  • A People field (point 2) covers extra roles such as Copywriter or Approver.
D11. Several assigneesYes; the first is the lead.
D12. Shows in and workloadOnly the lead’s Spaces are added through Shows in. Changing the lead follows the existing Shows in removal rule. Workload splits the hours evenly unless set per person.
Point 7

Start and due dates

ClickUp

  • Start date and due date, each with an optional time; the span drives the calendar, Gantt and workload.

Momentum today

  • Publishing date and due date. The due date is set by the rule, 7 calendar days before publishing, moved earlier off Friday and Saturday (Settings › Due Dates), or by hand.
  • No start date or times.

Proposed

  • Add an optional start date; the start can't fall after the due date.
  • The calendar can show tasks as spans from start to due.
  • Workload spreads the hour estimate over the working days between start and due (on the Settings weekend).
  • Times stay off; dates are Cairo days, as now.
D13. Default start dateEmpty unless set by hand or by a template.
D14. TimesDates only.
Point 8

Templates

ClickUp

  • Task templates save the fields, description, subtasks, checklists, assignees and dates relative to when the task is used. There are also List and Space templates.

Momentum today

  • No templates. Plans come in by Paste plan, and projects have steps.

Proposed

  • Task templates, each for one task type, hold:
    • the name pattern ("{Brand} · Monthly recap · {Month}") and the brief;
    • field values, priority and tags;
    • the assignee by role;
    • subtasks with dates set relative to the publishing date (for example, start 10 days before).
  • Used from "+ Task", the sheets, the calendar, and recurring tasks.
  • A task can be saved as a template.
D15. Managing templatesAdmins and superusers manage templates; everyone uses them.
D16. Editing a templateAffects new tasks only.
Point 9

Recurring tasks

ClickUp

  • A task repeats on a schedule (daily, weekly, monthly, custom) or when it's closed. ClickUp either creates a new copy or reopens the same task.

Momentum today

  • "Standing" projects with a target count per period (for example, 8 posts a month). Nothing is created automatically.

Proposed

  • A repeat rule on a task or template:
    • every N days or weeks on chosen weekdays, or monthly on a day;
    • it runs from the publishing date;
    • it can end on a date or after a number of times.
  • The next task is created ahead by a lead time before its publishing date: by default the due-date offset plus the type’s total SLA working days, and never less. It copies the type, brand, fields, tags, assignees and template subtasks, starts at To Do, and gets its due date from the rule.
  • Recurring tasks are marked ↻, with "Stop repeating" and "Skip next".
D17. When the next one is createdA lead time before its publishing date. The lead time is at least the due-date offset plus the type’s total SLA working days; that is the default, and a shorter lead time is refused.
D18. Standing projectsThey keep their targets; recurring tasks in a project count towards them.
