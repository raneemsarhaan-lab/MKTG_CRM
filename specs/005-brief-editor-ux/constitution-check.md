# Constitution Check: spec 005 (for the PR description)

Governance requires a Constitution Check note on PRs that introduce new components or state-shape changes. This is the note for the brief editor overhaul.

| Principle | How this PR meets it |
|---|---|
| **§I Design System Fidelity** | Every colour in the editor and its modules comes from `BRIEF_UI` in `src/lib/tokens.ts` (the blue + lime palette chosen in #80 and #81), mirrored once as `--brief-*` CSS variables in `globals.css`. A grep finds no hex or `rgba()` literal in `BriefEditor.tsx` or `brief-editor/`. Shadows use `alpha(BRIEF_UI.ink, …)`. `BRIEF_UI` extends the token map rather than amending §I, following the precedent of `STAGE_COLORS` and `STAT_CARD_TINTS`. **Follow-up:** `TaskModal`'s and `TaskForm`'s local `CU` constants hold the same values and should switch to `BRIEF_UI`; the new close-guard bar in `TaskModal` already uses tokens. |
| **§III Role-Based Feature Access** | Pasting or dropping an image uploads only when `TaskModal` passes `onUploadImages`, which it does only when `canEdit && hasStorage`. Otherwise the editor explains why and uploads nothing. The server route's `mayAttachTo` guard is unchanged. |
| **§IV Design-Driven Development** | `design/brief-editor-ux.html` was committed before any UI work (T001). It is the approved interactive preview: toolbar on desktop and phone, link card, "/" menu, table bar and resizing, save failure, click-to-edit, and Arabic. **Format:** it is plain, readable HTML rather than the compressed bundle used by `design/ui/*.html`. It meets the MUST (a standalone HTML design file that is the source of truth for layout, colours, interactions and copy) and needs no decompression step to read. Reviewers who want the bundle format, please say so. |
| **§V Cultural UX** | Every editor string lives in the `briefEditor` namespace of `messages/en.json` and `messages/ar.json`. A lab check confirms the key sets match and nothing is left untranslated. In Arabic the toolbar, menus, link card, table bar and "/" menu are right-to-left. |
| **§VI State Architecture** | No new persisted client state and no Zustand changes. Save state, overlays and upload jobs are local component state. The stored format is still Markdown in `tasks.description`; the only addition is the `data-*` size attributes on resized tables. |
| **Tech Stack** | `@tiptap/suggestion` 3.31.3, the official sub-package of the Tiptap version already in use, is added for the "/" menu. `axe-core` is added as a dev dependency for the lab's accessibility scan; it never ships to users. Neither is a new major dependency. |
